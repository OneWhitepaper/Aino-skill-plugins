# Project Planner

Build a plan that makes the next decision and next action clear.

## Establish the outcome

Extract the intended result, audience, current state, constraints and explicit
exclusions. Separate a desired outcome from a proposed solution. If a missing
fact changes the scope materially, ask a focused question; otherwise label a
reasonable assumption and keep moving.

## Map the work

Start from the deliverable and work backward. Group work by independently
verifiable outcomes. Identify prerequisites and dependencies before assigning
dates. Do not invent team members, commitments or precise estimates. When the
user asks for estimates without sufficient evidence, give a range and explain
what drives it.

For each milestone, specify what exists when it is done and how it can be
checked. Highlight the critical dependency and any decision that can delay
later work. Keep optional improvements separate from the minimum deliverable.

## Deliver the plan

Present scope, ordered milestones, acceptance criteria, key assumptions and
the immediate next action. Include owners and dates only when provided or
explicitly agreed. A plan is not authorization to send messages, spend money,
change production systems or start unrelated work.

When revising an existing plan, preserve completed work and explain the impact
of changed requirements on remaining dependencies and commitments.
